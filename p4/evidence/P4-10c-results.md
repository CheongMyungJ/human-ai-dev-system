# P4-10c 결과 — 기준 충족 종료 때 완료하지 않은 작업 표시 (D-97)

세션 S-037(2026-09-25). plan: [P4-PLAN-10c](../../plans/P4-PLAN-10c.md). 사용자 결정 **D-97**(선택지 A): 완료 규칙은 그대로(기준이 모두
충족되면 남은 계획 작업을 기다리지 않고 닫는다 — 이미 할 일이 없는 구현 작업은 "변경 없음 → 실패" 로 멈추기 때문), 대신 **완료하지 않고
끝난 작업**을 종료 종류와 함께 드러낸다.

## 1. 지금 제품이 하는 일

- **도출(저장 없음):** 종료 기록이 있는 업무에서 현재 작업 그래프의 작업 중 취소되지 않았고 완료되지 않은 것 — 실행하지 않았거나, 시도했지만
  (시간 초과 등으로) 끝내지 못한 작업. 이유는 종료 종류(`completed` 기준을 모두 충족해 종료 / `closed_with_exceptions` 예외를 수용해 종료 /
  `cancelled` 업무 취소). 종료 뒤에는 그래프 수정이 거부되고 작업 실행이 생기지 않아 값이 바뀌지 않는다. 스키마·종료 후보(해시) 무변경.
- **보이는 곳:** 작업 그래프 조회(`tasks[].not_run_at_closure`, `not_run_at_closure`, `closure_kind`), 대화 조회 `unrun_tasks`, 진행 이력 한 줄
  (`tasks_not_run` — 진행기가 완료를 볼 때 한 번), 진행 배너("완료하지 않은 작업 T3(기준을 모두 충족해 종료 — 필요하면 새 대화로 요청)"),
  작업 탭 작업 행("완료하지 않고 종료 — …").
- **완료 규칙·판정·권한은 그대로다.** 기준이 미충족이면 업무가 닫히지 않으므로 남은 작업은 평소대로 돈다.

## 3. 한계

- 기준에 이어지지 않은 작업(문서·정리 등)은 기준이 충족되면 실행되지 않는다 — 필요하면 성공 기준으로 적거나 종료 뒤 새 대화로 요청한다(D-97 의
  알려진 한계). 표시는 사실의 기록이며 그 작업의 필요성을 판정하지 않는다.
- 종료 전 조회에는 나오지 않는다(진행 중에는 작업 그래프의 상태가 그대로 보인다).

## 0. 제품 판단

**새 제품 판단은 사용자가 내렸다(D-96)** — 전부 허용, 읽기 전용은 도구로 제한, Codex 읽기 전용은 감지·알림(실패 아님). 상세 설계 선택:

- **인자:** codex 두 권한 모두 `--dangerously-bypass-approvals-and-sandbox`(샌드박스·승인 없음). claude 두 권한 모두
  `--dangerously-skip-permissions` + `--strict-mcp-config`(외부 서비스 MCP 는 계속 막음 — D-91 의 상세 설계 선택 그대로), 읽기 전용만
  `--tools Read,Grep,Glob`(쓰기·실행 도구가 아예 없다). 쓰기 권한 없는 매핑(`explicit_escalated`)은 그대로 없다.
- **감지 대상:** 읽기 전용 실행이 도는 폴더(작업공간이 있으면 worktree, 없으면 원래 저장소)와, 작업공간이 있으면 원래 저장소도.
  git 저장소가 아니거나 관측에 실패하면 `unobserved` 로 적는다(바뀌지 않음으로 읽지 않는다). 지문은 P3-03 의 `workspace.observe`
  (HEAD·미커밋 diff·미추적 파일 blob) — `.gitignore` 된 파일과 저장소 밖은 보지 않는다.
- **올리는 것은 사실뿐:** `{observed, changed, where[], unobserved[]}` — 경로·본문 없음(D-43). 제어부는 `run.read_only_change_json`
  (v29 에 더함)에 적는다. **결과·판정은 바꾸지 않는다**(사용자 결정 — 실패 아님).
- **알림:** 진행 이력 한 줄(`read_only_changed`), 대화 목록 행의 수 `read_only_changes` → 브라우저 알림 종류 `read_only_change`
  (그 수가 늘면), 대화 화면 배너(실행별, 실행 상세로 이동), 작업 탭 실행 상세. 누가 바꿨는지는 모른다 — 같은 폴더의 다른 실행·사람의
  편집도 잡힐 수 있어 "이 실행 동안 바뀌었다" 로 적는다.
- **능력 보고:** `read_only_enforcement` — codex `unsupported`(D-96: 막지 않고 감지만), claude `doc_only`(`--tools` 제한, 실제 CLI
  미실증). `permission:read_only` 의 근거를 D-96 으로 바꾼다.
